# סוף דבר

> סוֹף דָּבָר הַכֹּל נִשְׁמָע אֶת הָאֱלֹהִים יְרָא וְאֶת מִצְוֺתָיו שְׁמוֹר כִּי זֶה כׇּל הָאָדָם.
> — קהלת יב, יג

מאגר שאלות ותשובות בהלכה וביהדות. Flask + SQLite בצד השרת, HTML ו-CSS בצד הלקוח,
בלי צעד בנייה ובלי מסגרת JavaScript.

## הרצה

```bash
pip install -r requirements.txt
python scripts/build_db.py     # בונה את data/sofdavar.db מקבצי ה-seed
python run.py                  # http://127.0.0.1:5000
```

## תוכן

### הוספת שאלות

**פקודה אחת, תמיד:**

```bash
python scripts/update.py                    # אחרי עריכה ידנית של questions.json
python scripts/update.py my-questions.csv   # אחרי הכנת קובץ חדש
python scripts/update.py my-questions.csv --dry-run
```

היא מריצה ארבעה שלבים ברצף: ייבוא אל `data/seed/questions.json`, שיבוץ קוד
קבוע לכל שאלה חדשה, חישוב ווקטורים לחדשות ולמה שהשתנה בלבד, ובנייה מחדש של
המסד. הקובץ יכול להיות CSV או JSON, עם כותרות בעברית או באנגלית; המבנה מתועד
בראש `scripts/import_questions.py`, והקידוד מזוהה אוטומטית כולל cp1255 של
Excel בעברית.

> ⚠ **אל תריצו `scripts/import_questions.py` ישירות.** הוא כותב **למסד בלבד**,
> ואילו `scripts/build_db.py` מוחק את המסד ובונה אותו מחדש מקבצי ה-seed —
> כלומר הבנייה הבאה תמחק את כל מה שיובא, בלי הודעה. `update.py` נכתב בדיוק
> כדי לסגור את הפער הזה: הוא מייבא אל קובץ המקור, ומשם הכול נבנה.
> `import_questions.py` נשאר ככלי פירוק ה-CSV ש-`update.py` משתמש בו.

קטגוריה שאינה מוכרת **מפילה את הבנייה** במקום להידלג בשקט. שאלה שממתינה
לנושא נשמרת ב-`data/seed/questions_pending.json` ואינה נטענת.

### מדידת החיפוש

```bash
python scripts/eval_retrieval.py                  # הכול
python scripts/eval_retrieval.py --source owner   # רק שאילתות שנכתבו בידי אדם
```

משווה ארבע שיטות על `data/eval/queries.json` ומדפיס Recall@1, Recall@5, MRR,
אחוז אפס-תוצאות והימנעות. הריצו אחרי כל הוספת תוכן כדי לראות אם המספרים זזו.

### הוספת פוסט לבלוג

קובץ `.md` חדש ב-`content/blog/`, עם front-matter:

```markdown
---
title: כותרת הפוסט
description: תקציר במשפט אחד למנועי חיפוש
date: 2026-07-20
tags: הלכה, שבת
---

גוף הפוסט ב-Markdown.
```

הפוסט מופיע מיד. אין צורך להריץ כלום.

## המספור

לכל שאלה יש מספר רץ אחד לכל האתר, שאינו מתאפס בין נושא לנושא: אם בנושא הראשון
שלוש שאלות, הראשונה בנושא הבא היא שאלה 4. המספר נגזר מסדר הקטגוריות ומסדר
השאלות בתוכן, ולכן הוא יציב בין ריצות — אבל **לא** בין תוכן לתוכן: שאלה שנוספת
בקטגוריה מוקדמת מזיזה את כל מי שאחריה. לכן המספר הוא תצוגה וציטוט, ולא כתובת.

## הכתובת של עמוד שאלה

`/q/k7m2` — ארבעה תווים, ASCII בלבד.

הכתובת הייתה `/<קטגוריה>/<slug עברי>`, ושלוש בעיות היו בה: היא הפכה ל-400 תווים
של אחוזי-קידוד, היא נשברה בשיתוף בוואטסאפ, וכל תיקון בנוסח השאלה שינה אותה
והפיל כל קישור ישן.

הקוד נשמר ב-`data/seed/questions.json` ליד השאלה עצמה, כי המסד נבנה מחדש בכל
פריסה. אחרי הוספת שאלות:

```bash
python scripts/assign_codes.py    # משבץ קוד לכל שאלה שאין לה, ולא נוגע בקיימות
```

הסקריפט אידמפוטנטי, והתוצאה נכנסת ל-git יחד עם השאלות. קוד קיים לא משתנה
לעולם — שינוי שלו שובר כל קישור שכבר פורסם.

כל הכתובות הישנות ממשיכות לעבוד ומפנות ב-301 אל הכתובת הקבועה:

| כתובת | תוצאה |
|---|---|
| `/q/k7m2` | העמוד עצמו |
| `/q/k7m2/מוקצה-בשבת` | 301 → `/q/k7m2` (סיומת דקורטיבית מותרת) |
| `/q/47` | 301 → `/q/k7m2` (קיצור לפי המספר הרץ) |
| `/shabbat/<slug עברי>` | 301 → `/q/k7m2` (הכתובת הישנה) |

## חיפוש

SQLite FTS5, עם נרמול עברי בשני הצדדים — גם בטקסט שנכנס לאינדקס וגם בשאילתה:

* ניקוד וטעמים מוסרים, ולכן «שַׁבָּת» מוצא «שבת»
* אותיות סופיות מאוחדות
* אותיות שימוש (ו, ה, ב, כ, ל, מ, ש) נחתכות, ולכן «בשבת» מוצא «שבת» ולהפך
* התאמת תחילית, כך שהשלמה אוטומטית עובדת מהתו השני

החיפוש מחזיר נושאים ושאלות מסומנים בסוגם. עמוד `/search` עובד גם בלי JavaScript.

## זמנים

החישוב אסטרונומי (NOAA) ונעשה בשרת, **בגובה פני הים** כמו ברוב הלוחות המקובלים.
אין קריאות רשת בזמן ריצה.

זמן הדלקת הנרות אינו חישוב אלא מנהג המקום, ולכן הוא נתון לכל עיר בנפרד
ב-`app/zmanim.py` יחד עם מקור המנהג.

לאימות מול Hebcal:

```bash
python scripts/verify_zmanim.py --days 12
```

הסקריפט משווה 14 זמנים בארבע ערים לאורך שנה, בסבילות של דקה. הוא כלי פיתוח
בלבד — יש להריץ אותו אחרי כל שינוי ב-`app/zmanim.py`.

## SEO

* כותרת, תיאור, `canonical`, Open Graph ו-Twitter לכל עמוד
* `FAQPage` (JSON-LD) בעמודי השאלות, `BlogPosting` בפוסטים, `BreadcrumbList` בכולם
* `sitemap.xml` נבנה אוטומטית מהמאגר
* `robots.txt` חוסם את `/search` ואת `/api/`

עמודי הקטגוריה נושאים `canonical` **עצמי** ולא מפנים לעמודי השאלות: הפניה כזו
הייתה מוציאה אותם מהאינדקס לגמרי. במקום זה, האקורדיון בעמוד הקטגוריה מציג רק
את התשובה הישירה, והתוכן המלא נמצא רק בעמוד השאלה — כך אין תוכן כפול.

לפני עלייה לאוויר יש להגדיר את הדומיין:

```bash
export SOFDAVAR_SITE_URL=https://example.co.il
```

* תיבת החיפוש היא combobox לפי תקן ARIA: ניווט בחצים, Enter, Escape,

* מצב כהה ובהיר, נשמר ב-`localStorage`, בלי הבזק בטעינה
* כל עמוד עובד בלי JavaScript
